## 三、方案取舍

### 1. 用 gopsutil 还是自己读 /proc —— 采用 gopsutil

- 自己实现需要 `syscall.Statfs`（磁盘）和 `/proc/stat`、`/proc/meminfo`（CPU、内存）。`syscall.Statfs` 在 Windows 下不存在，在 darwin 下字段也不同。而 `util/os.go:129` 说明本库必须能在 Windows 下编译。自己实现就得按 build tag 拆成多个平台文件，既超出了交付路径 `os.go`，也违背「最小改动」。
- gopsutil 是 Go 生态里读取系统指标的事实标准，三个平台都支持。已验证 `GOOS=windows` 和 `GOOS=darwin` 都能编译通过。每个函数只是 5~8 行的薄封装，符合「复用优先」。

### 2. CPU核数：用 `cpu.Counts(true)`，不用 `runtime.NumCPU()`

- 使用率的数据来自 `/proc/stat`，它覆盖全部在线 CPU。而 `runtime.NumCPU()` 受进程 CPU 亲和性影响，比如 `--cpuset-cpus` 会让它变小。为了满足「两核CPU、150%」这个例子的口径（使用率上限 = 核数×100），核数必须和使用率用同一个统计口径，所以用 `cpu.Counts(true)`。
- 取逻辑核而不是物理核：使用率是按逻辑 CPU 统计的，超线程的每个线程都算一核。

### 3. CPU使用率：按核累加，interval 由调用方传入

- 用 `cpu.PercentWithContext(ctx, interval, true)` 拿到每个核的使用率（0~100），再求和，得到 `[0, 核数×100]`。这正好对应需求里「两核CPU使用率150% = 用了1.5核」。
- 没有用「归一化值 × 核数」的写法：那样要多读一次核数，两次读取之间还可能不一致。
- `interval` 作为参数传入，没有在函数里写死一个采样时长（写死相当于在函数内部埋一个魔法数，也会让调用方意外阻塞）。
  - `interval > 0`：阻塞 interval 时长，取这段时间内的使用率；ctx 取消时会立即返回 error。
  - `interval <= 0`：不阻塞，取与上次调用（全进程共享，第一次调用时以 gopsutil 包初始化为起点）之间的均值。这是 gopsutil 的原生语义，只在注释里写明，没有额外编码。

### 4. 内存已使用：总内存 − 可用内存（Total − Available）

- gopsutil v4.26.9 在 Linux、Windows、FreeBSD 上的 `Used` 都是 `Total - Available`，直接复用它的 `stat.Used`。
- 这个口径和 procps `free` 命令的「已用」列完全一致，见第五节实测。它不包含可回收的 page cache/slab，能反映真实的内存压力，适合做告警。

### 5. 磁盘：按 path 指定分区

- 「磁盘大小」只有落到具体挂载点上才有确定含义，底层的 `statfs` / `GetDiskFreeSpaceExW` 也必须传路径。所以函数接收 `path`，返回 path 所在分区的数据，调用方传 `/`、数据目录或 `C:\` 都可以。
- 没有选「所有分区求和」：bind mount、overlay、tmpfs 会被重复计算，口径不可靠。
- `Used = (Blocks - Bfree) * Bsize`，和 `df` 的 Used 一致。注意 `Used + 可用 ≠ Total`，差值是 ext4 等文件系统给 root 预留的块，这是正常现象。

### 6. 返回值与异常处理

- 签名统一为 `(值, error)`，和 `ExecCommand`、`GetWxOpenIdList` 一致。调用方必须能区分「真的是 0」和「读取失败」，所以不像 `GetHome()` 那样吞掉错误。
- 写法沿用 `wechat.go` 的 `err != nil || resp == nil` 合并判断。额外拦截了 `num <= 0`、`len(percents) == 0`、`stat == nil` 这些「err 为 nil 但结果不可用」的情况，避免把 0 当成有效数据返回（核数为 0 还会导致调用方除零）。
- 字节数用 `uint64`，和 gopsutil 原生类型一致，避免转换和溢出。
- 遵守「严禁过分细拆函数」：只写需求要求的 6 个函数，不抽公共 helper。内存和磁盘的 total、used 各自调用一次底层接口，同时需要两个值时会多读一次，开销是微秒级，可以接受。

| 影响 | 说明 |

| 阻塞 | `GetCpuUsage` 在 interval>0 时会阻塞 interval 时长，不要在请求热路径里用 |
| 已有函数 | 没有任何改动 |
